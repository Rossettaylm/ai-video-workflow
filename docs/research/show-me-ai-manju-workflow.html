一句话：主流做法不是“一句话出整剧”，而是以镜头为最小可替换单元的工业化流水线： 结构化剧本 → 角色/场景资产库 → 分镜关键帧 → 逐镜图生视频（3–30 秒）→ 配音/局部口型 → 剪辑合成 → 合规审核发布， 并保留 4 个人工闸门。

新手最容易混淆的三组概念

剧本 ≠ 分镜

剧本写“发生了什么、谁说了什么”，像小说。

分镜写“观众看到什么画面”，是一张表格，每行一个镜头，带时长、景别、运镜。AI 画图和生成视频吃的是分镜，不是剧本。

关键帧 ≠ 视频

关键帧是一张静态图，便宜、快、容易修改。

视频是让这张图动起来的几秒片段，贵、慢、改不动。所以流程上永远是先把图定稿，再生成视频。

IP ≠ IP-Adapter

IP在影视圈指原著版权，比如一部网文小说，改编前要买授权。

IP-Adapter是一个 AI 技术名，这里的 IP 是 Image Prompt（图像提示），用来让模型参考一张图画角色。两者毫无关系。

02核心原则：逐镜生产，而非一键整剧

✗ 一次文生长视频

prompt("第 1 集全部剧情")
  → 视频模型
  → 角色漂移 / 动作丢失 / 无法局部修
  → 整集重抽

✓ 镜头为最小可替换单元

for shot in shots.json
  keyframe = 生成首帧(资产 ID 引用)
  if 人审不通过 → 只重跑这一镜
  clip = I2V(keyframe, 上一镜尾帧)
  记录 provider / seed / 成本 / hash
拼接 → 成片
右边这段像代码，但意思很简单：按分镜表一行一行做。每行先画图，人看过没问题再生成视频；把这一镜的尾帧当成下一镜的起点，画面就能接上。“seed / hash”是记账用的编号（见术语表），方便以后复现或查花费。

03角色一致性的五层叠加

① 语义层固定姓名、年龄、体型、发型、服装主色、标志物、禁改项（角色 bible）
② 视觉资产层正面 / 3/4 / 侧 / 背 / 表情表，同一造型使用不可变 asset ID
③ 参考控制层每张分镜显式传入角色、服装、场景、道具参考图（Seedream / FLUX.2 / IP-Adapter）
④ 模型定制层高频主角再训练 LoRA / DreamBooth，MVP 首版先不训练
⑤ 时间连续层上一镜尾帧作为下一镜首帧；StoryMem 一类关键帧记忆库
“一致性”就是主角在第 1 镜和第 100 镜看起来是同一个人。新手只需要做好前三层：写清外貌关键词 → 定一套标准照 → 每次画图都把标准照作为参考图传进去。第四层要训练模型，等真的做成长剧再考虑。

05合规：三条独立链路

AI 内容标识

  • 起始画面显式标识，含“AI/人工智能”与“生成/合成”
  • 字高 ≥ 最短边 5%，持续 ≥ 2 秒（GB 45438-2025）
  • 文件元数据隐式标识，不得删改

微短剧审核（2026-09-01 起）

  • 一/二/三类分类审核，无许可或节目编号不得播出
  • AI 制作的微短剧每集明显位置提示
  • 首集片头或末集片尾署名编剧、导演

权利授权

  • 小说改编权 + 信息网络传播权
  • “融像”“融声”须取得权利人明确授权
  • 字体、音乐、模型、LoRA 许可证逐项登记
算一下“5%”有多大：竖屏 1080×1920 的最短边是 1080 像素，所以“AI 生成”这几个字至少 54 像素高，并且在片头显示至少 2 秒。剪映里加一个文字贴纸就能做到。不要用别人的小说、明星的脸或声音，哪怕只是练手发出去也有风险。

06选型避坑（截至 2026-10-19）

Sora 2 API：已关停

Videos API 与 sora-2 / sora-2-pro 于 2026-09-24 下线，官方未给出替代模型。

Kling 4.0 API：未开放

10-15 已在产品端上线，API 仍为“即将开放”；可用于人工精修关键镜头，暂不写进自动化依赖。

Wan2.2：显存门槛高

官方 720P I2V 单卡命令需 ≥ 80GB 显存；单张 4090 起步选 HunyuanVideo-1.5。

07只用过 WorkBuddy？从你熟悉的东西出发新手专区

WorkBuddy 是腾讯的桌面 AI 智能体工作台：你用一句话下任务，它会拆步骤、调用工具、读写本地文件，最后交付结果。这套“说需求 → 拆步骤 → 调工具 → 交文件”的模式，就是漫剧流水线的骨架，你已经会了一半。

你已经会的

用自然语言描述任务；让它产出文档、表格；调用“专家”和 Skill；授权它读写某个文件夹；把长任务交给云端助理。

这些能力直接覆盖了漫剧的阶段 1–2（剧本、分镜表）、阶段 7 的整理工作，以及全流程的项目文件管理。

你还缺的一块

WorkBuddy 是“指挥台”，不是“摄影棚”。高质量的角色图和视频片段来自外部生成模型（即梦 / Seedance、可灵、Vidu 等），需要单独的账号、积分或 API 额度。

把问题列成清单，先不要改文件，等我确认。

Day 6配音 + 剪辑

在剪映里导入全部片段按镜号排列；用剪映的文本朗读或豆包语音生成台词配音；自动识别字幕后人工校对；片头加“本内容由 AI 生成”文字，字高至少 54 像素、显示至少 2 秒。

工具：剪映 · 对应阶段 6–7 · 人工闸门④：完整看一遍成片
Day 7复盘

让 WorkBuddy 读取分镜表里的记录，统计：角色走样的镜头数、平均每镜重试次数、总花费、哪一步最耗时间。这份复盘决定你下一步走 L1 还是 L2。

用 WorkBuddy 做漫剧时的四个提醒

第三方 Skill 先看再装

WorkBuddy 官方文档提示：非官方 Skill 可能存在提示词注入、越权访问、后门等风险，还可能把输入发给第三方。优先用官方推荐，装之前看权限和脚本。

API key 不进项目文件

API key 等于钱包钥匙。不要写进剧本、分镜表或会分享的文件夹；Drama Skills 也是这么设计的：供应商凭据不进入项目。

先预览，再花钱

生图、生视频都按次计费。让智能体先把这一批的提示词、数量、参数列出来给你看，你确认后再提交，这是 Drama Skills 的核心做法。

积分会比想象中消耗得快

WorkBuddy 官方提示复杂任务和复杂 Skill 积分消耗较高；视频模型同样按秒或按次计费。从 1 集、10 个镜头起步，先算清单镜成本。
