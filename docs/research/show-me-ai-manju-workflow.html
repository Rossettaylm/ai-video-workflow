AI 漫剧生成工作流 · 全景图

调研日期 2026-10-19 · 详细出处见同目录 ai-manju-workflow.md

一句话：主流做法不是“一句话出整剧”，而是以镜头为最小可替换单元的工业化流水线： 结构化剧本 → 角色/场景资产库 → 分镜关键帧 → 逐镜图生视频（3–30 秒）→ 配音/局部口型 → 剪辑合成 → 合规审核发布， 并保留 4 个人工闸门。

02核心原则：逐镜生产，而非一键整剧

✗ 一次文生长视频

prompt("第 1 集全部剧情")
  → 视频模型
  → 角色漂移 / 动作丢失 / 无法局部修
  → 整集重抽

✓ 镜头为最小可替换单元

for shot in shots.json
  keyframe = 生成首帧(资产 ID 引用)
  if 人审不通过 → 只重跑这一镜
  clip = I2V(keyframe, 上一镜尾帧)
  记录 provider / seed / 成本 / hash
拼接 → 成片

03角色一致性的五层叠加

① 语义层固定姓名、年龄、体型、发型、服装主色、标志物、禁改项（角色 bible）
② 视觉资产层正面 / 3/4 / 侧 / 背 / 表情表，同一造型使用不可变 asset ID
③ 参考控制层每张分镜显式传入角色、服装、场景、道具参考图（Seedream / FLUX.2 / IP-Adapter）
④ 模型定制层高频主角再训练 LoRA / DreamBooth，MVP 首版先不训练
⑤ 时间连续层上一镜尾帧作为下一镜首帧；StoryMem 一类关键帧记忆库

04技术难点：现在能解决到哪一步

难点当前有效解法仍未解决
角色一致性bible + 四视图 + 多参考 + 高频角色 LoRA + embedding 自动 QA复杂表情、极端角度、多角色遮挡
场景一致性场景母版空镜、3D 白模、深度/线稿控制大幅运镜下的完整空间记忆
动作可控一镜一动作、首尾状态、动作参考视频、3D 预演长时复杂交互、精细手部
跨镜连续尾帧承接、首尾帧、服装/场景状态机多角色跨场次长程记忆
口型同步先锁音频、只做特写、LatentSync / Hedra / 可灵对口型大角度、遮挡、多人抢话
长剧情连贯事件图、setup/payoff 表、每集状态快照LLM 隐性矛盾，需人工编审
成本产能低清预览 → 人选 → 高清；hash 缓存；预算上限行业缺统一成本口径

05合规：三条独立链路

AI 内容标识

  • 起始画面显式标识，含“AI/人工智能”与“生成/合成”
  • 字高 ≥ 最短边 5%，持续 ≥ 2 秒（GB 45438-2025）
  • 文件元数据隐式标识，不得删改

微短剧审核（2026-09-01 起）

  • 一/二/三类分类审核，无许可或节目编号不得播出
  • AI 制作的微短剧每集明显位置提示
  • 首集片头或末集片尾署名编剧、导演

权利授权

  • 小说改编权 + 信息网络传播权
  • “融像”“融声”须取得权利人明确授权
  • 字体、音乐、模型、LoRA 许可证逐项登记

06选型避坑（截至 2026-10-19）

Sora 2 API：已关停

Videos API 与 sora-2 / sora-2-pro 于 2026-09-24 下线，官方未给出替代模型。

Kling 4.0 API：未开放

10-15 已在产品端上线，API 仍为“即将开放”；可用于人工精修关键镜头，暂不写进自动化依赖。

Wan2.2：显存门槛高

官方 720P I2V 单卡命令需 ≥ 80GB 显存；单张 4090 起步选 HunyuanVideo-1.5。

市场规模（艾媒 189.8 亿 / DataEye 168 亿，均为 2025 年）属于第三方估算且口径冲突；红果分成、即梦 Octo、快手“造梦专家 2.0”、B 站专项规则均未找到一手资料。 完整证据链见 ai-manju-workflow.md。
